2026-11-11. 기존 홈페이지(Vercel + Supabase)에 구현. Sites의 예전 정적 배포 설정은 사용하지 않는다.

## 화면

- `/auditions`: 공개 공고 목록. 공고별 공유 주소는 `/auditions/<공고 ID>` (기존 쿼리 주소는 301 이동).
- `/admin/casting`: 기존 관리자 로그인으로 공고 작성·수정·게시·마감, 지원서 조회, 배역·상태·이름·연락처 필터, 검토 상태·메모, 프로필 다운로드, CSV, 지원서·프로필 삭제.
- 홈페이지의 공지사항 옆에 공개 오디션 메뉴, 기존 편집기의 관리 메뉴에 오디션 공고·지원자 메뉴를 추가한다.
- 첫 공고는 관리자 화면의 `《악인의 방식》 양식으로 시작`으로 작성한다. 자동 게시하지 않으며 게시 전까지 비공개 초안이다.
- 네이버 원본의 19개 질문을 공통 지원서로 구현했다. 공고별 배역·날짜·촬영 일정·주최를 변경할 수 있다. 임의 설문 문항 추가 도구는 포함하지 않는다.
- 배우는 회원가입 없이 지원할 수 있다. 프로필 문서 1개, 10MB 이하, 영상 2개는 링크 제출. 문서 형식 PDF/DOC/DOCX/PPT/PPTX/XLS/XLSX.
- CSV는 **현재 불러온 목록에 적용한 필터 결과**만 내보낸다. 100명씩 더 불러오며, 파일 내 수식으로 실행될 수 있는 값은 이스케이프한다. 내려받은 CSV 사본은 운영자가 별도로 파기한다.
- 상태 변경은 내부 관리용이다. 문자·메일·합격 안내를 자동 발송하지 않는다.

1. 현재 Supabase 프로젝트에 `supabase/migrations/20261111_casting.sql`, `supabase/migrations/20261111_casting_dashboard.sql`, `supabase/migrations/20261111_casting_workflow.sql` 순서로 적용한다. 전용 공고·지원서·요청 제한 테이블, 원자적 접수 함수, 비공개 프로필 버킷이 생성된다. 기존 회원·상담 자료는 변경하지 않는다.
2. Vercel의 기존 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_SESSION_SECRET`(32자 이상), `ADMIN_PASSWORD`를 유지한다. 키를 클라이언트에 전달하지 않는다. 2026-11-11 운영 DB에 오디션 마이그레이션 3개를 적용하고 전용 집계 함수 응답을 확인했다.
3. 기존 운영 소스에 이번 변경만 반영해 빌드·배포한다. 작업 폴더에 이전 작업의 미반영 변경이 많으므로 전체 변경을 무조건 배포하지 않는다.
4. 관리자 로그인, 초안의 공개 접근 차단, 파일 1개 업로드·실제 접수, 관리자 파일 다운로드, 만료된 다운로드 링크 거부를 운영 환경에서 검증한다. 실제 지원자는 이 확인 이후 받는다.
5. 공고의 시간·본문을 확인하고 공개로 저장한다. 시작 전에는 안내만 표시하고, 기간 안에만 지원서를 받는다. 종료 시각부터 접수를 거부한다.

## 보관·파일 접근

- 공개 API는 공고만 조회한다. 지원서 조회·메모·삭제·파일 링크 발급은 관리자 인증과 동일 출처 검사를 거친다.
- 프로필은 전용 **비공개** 버킷에 무작위 경로로 저장한다. 업로드 서명은 공고·파일 정보에 결합하고 2시간 만료, 덮어쓰기 금지. 접수 시 실제 파일 크기·형식을 확인한다.
- 관리자 다운로드는 60초간 유효한 링크를 사용한다. 다운로드 링크를 타인에게 전달하지 않는다.
- 지원서와 접수 당시 개인정보 안내(주최·공고명·보관기간)를 함께 보관한다. 보유 기한은 제출일부터 1년.
- 관리자 화면에서 개별 지원서와 파일을 함께 영구 삭제할 수 있다. 화면에서 삭제 확인을 받는다.
- `node --env-file=.env.local scripts/casting-maintenance.cjs`는 **삭제 없이** 만료 지원서와 제출되지 않은 3일 이상 된 업로드 수만 확인한다. `--apply`를 추가하면 만료 지원서·프로필, 미제출 파일, 만료 요청 제한 기록을 삭제한다. 실제 운영에서는 이 정리 작업을 매일 실행하는 운영 작업이 필요하며, 이번 작업에서 일정을 등록하거나 실제 자료를 삭제하지 않았다.
- 접수 요청 제한은 별도 테이블에서 IP별 15분에 30회(업로드 발급·제출 각각 1회)를 적용한다. 기존 AI 이용량과 공유하지 않는다.

## 배역 카드와 지원자 현황 (2026-11-11 추가)

- 관리자 공고 카드는 접수 기간·오디션 일정·촬영 일정·모집 배역·전체 지원 인원을 나눠 표시한다. 긴 원문은 상세 화면에서 펼쳐본다.
- 공고 클릭 → 배역 카드 → 해당 배역 지원자 카드 → 지원서 상세로 이동한다. 공고·배역별 화면은 주소를 공유하거나 새로고침해도 다시 열 수 있으며 항상 관리자 로그인을 요구한다.
- 배역별 인원은 전체 저장된 지원서를 서버에서 집계한다. 복수 지원은 각 배역에 포함하고 전체 지원자는 한 번만 센다. 이 수치는 접수 중인 작성자가 아니라 **제출이 완료된 지원서 수**다.
- 이름·연락처·배역·상태 필터는 서버의 전체 자료에 적용한 뒤 100명씩 가져온다. 총 검색 건수와 현재 표시 건수를 구분한다. CSV는 표시된 명단만 내보낸다.
- 집계는 화면 진입 및 새로고침 시 갱신한다. 실시간 접속 인원이나 자동 AI 심사는 구현하지 않았다.
- `--demo --casting-showcase`로 실행하면 별도 메모리에 가상 지원자 14명과 배역별 예시 수치를 생성한다. 운영 데이터가 아니며 DB에 쓰지 않는다. 시연 파일 다운로드는 실제 파일을 첨부한 테스트 지원서에서만 가능하다.
- 101개 지원서 SQL 검사로 첫 100개 이후 지원자의 검색·집계를 확인했다. 익명 사용자는 집계 함수와 검색 함수에 접근할 수 없다.


## 메인 카드와 검색 노출 (AEO/GEO)

- 메인 첫 화면 아래에 최대 3개의 공개 오디션 카드를 보여준다. 마감 공고는 메인에서 제외하며, 공고가 없거나 연결에 실패하면 안내와 전체 공고 링크를 제공한다. 한 개는 넓은 대표 카드, 여러 개는 반응형 목록이다.
- `/auditions`, `/auditions/<UUID>`는 서버에서 공개 본문·배역·접수 기간·오디션 장소·준비 자료를 HTML로 제공한다. 자바스크립트를 실행하지 않는 검색 로봇도 읽을 수 있다. 각 공고의 고유 주소·제목·설명·공유 미리보기·WebPage/CollectionPage·BreadcrumbList·ItemList를 실제 공개 내용으로 구성한다.
- 조건이 없는 급여·고용 형태·합격률 등을 만들어 JobPosting에 넣지 않는다. 개인화 검색을 위한 지원자 정보 공개나 AI 심사도 하지 않는다.
- `/auditions-sitemap.xml`은 공개 중이며 마감되지 않은 공고를 조회해 자동 갱신한다. 생성 시각 대신 실제 공고 수정 시각을 사용한다. robots.txt에서 이 사이트맵을 안내한다. 기존 User-agent: * 허용 규칙으로 Googlebot·OAI-SearchBot의 공개 페이지 접근을 허용하며, 관리자·지원서 수정·API 경로는 제외한다. 로봇 차단은 접근 제어를 대체하지 않는다.
- 비공개·없는 공고는 404, 저장소 장애는 503, 마감된 공고는 noindex다. 관리자 메모·지원자 정보는 공개 페이지나 구조화 데이터에 들어가지 않는다.
- 운영 배포 후 Search Console/Bing Webmaster/Naver Search Advisor에 사이트맵 제출 및 URL 검사, 공개 공고의 검색 유입을 확인한다. 외부 검색 서비스의 색인·인용·순위는 보장할 수 없으며, 지원자가 ChatGPT에 저장한 개인정보를 사이트에서 읽을 수 없다.
- 근거: https://developers.google.com/search/docs/appearance/ai-features / https://developers.openai.com/api/docs/bots

## 지원자 본인 수정

- 접수 성공 응답에 접수번호와 서명된 수정 키를 전달한다. 완료 화면에서 `/audition-edit#id=...&key=...` 링크를 보관·복사한다. 키는 URL fragment에 있어 서버 URL·검색 주소로 전송되지 않으며, API에는 동일 출처 POST 본문으로 전달한다.
- 링크를 가진 사람은 해당 지원서를 열 수 있다. 이메일/SMS 본인인증 또는 링크 분실 복구는 제공하지 않는다. 운영자는 민감한 링크가 공유되지 않도록 안내해야 한다. ADMIN_SESSION_SECRET을 바꾸면 기존 수정 링크가 모두 무효화된다.
- 접수 마감 전 수정, 프로필 유지/교체를 지원한다. 공고·지원서 변경 충돌을 검사하고, 관리자 메모·처리 상태·AI 요약·파일 저장 경로는 수정 API에 노출하지 않는다. 수정해도 원래 보관 만료일은 연장되지 않는다. AI 요약은 초기화되어 변경된 자료로 다시 검토한다.
- 교체된 파일은 기존 3일 이상 미참조 파일 정리 작업으로 제거한다. 실제 정리 작업의 운영 등록은 필요하다.

## 관리자 운영실과 요약

- 공고 → 배역별 지원 현황 → `시간표 · 안내문 · 보고서`로 접근한다.
- 접수 보고서는 전체 지원서를 한 번의 DB 조회 기준으로 집계한다. 배역·처리 상태·참석 가능일과 오늘 접수 수를 확인하고 CSV로 내려받는다.
- 시간표는 참석 가능일이 적은 지원자를 우선하고 동일 조건에서는 접수 순으로 배정한다. 관리자 설정은 시작·종료 시간, 1인당 5~120분, 심사실 1~5개다. 배역 적합성이나 합격을 판정하지 않는다. 별도 협의·정원 초과는 미배정으로 표시한다.
- 시간표를 직접 조정해 초안 저장 또는 검토 완료로 확정한다. 중복 시간/심사실, 중복 사람, 가능일 불일치를 서버에서 거부한다. 지원서·공고 변경 또는 다른 관리자 저장 시 이전 상태로 덮어쓰지 못한다. 지원서 revision이 바뀌면 기존 시간표는 재확인이 필요하다.
- 확정된 최신 시간표에서 이름·일시·장소·심사실을 넣은 안내문을 만든다. 공통 양식 저장, 개별 문구 수정·복사, 전체 CSV를 제공한다. **문자·메일 전송 서비스는 연결하지 않았으며 실제 발송하지 않는다.**
- AI 요약은 지원자의 별도 선택 동의와 관리자의 전송 확인 후 진행한다. 프로필 문서 전체와 입력 경력·특기를 OpenAI Responses API로 전송한다. 문서 안에 사진·연락처가 포함될 수 있음을 지원 화면에 알린다. 기존 OPENAI_API_KEY/OPENAI_MODEL 설정을 사용하고 store:false, 구조화된 결과, 60초 제한을 적용한다. 이 옵션이 제공자의 모든 보관을 없앤다는 의미는 아니다.
- 결과는 최대 8개의 경력·특기 사실과 원문 인용이다. 입력란 인용은 실제 문자열과 대조한다. 문서 인용은 AI 추출값이므로 담당자가 원문을 확인해야 한다. 점수·순위·자동 합격·외모/성격 추론을 하지 않는다. 동의하지 않은 사람은 원문 검토를 계속할 수 있다.
- 요약 중 지원서가 수정되면 오래된 요약 저장을 거부한다. 기존 요약 재조회는 외부 API를 다시 호출하지 않는다. 시연 환경은 입력 경력으로 예시를 만들며 외부로 전송하지 않는다.
