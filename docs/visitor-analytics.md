# 방문 통계

공개 홈페이지는 Vercel Web Analytics로 방문자 수, 페이지 조회 수, 유입 경로, 국가와 기기 정보를 집계합니다.

- 통계 화면: https://vercel.com/peter15975345-8667s-projects/scene-academy/analytics
- 접속 방법: 홈페이지 관리자 편집 화면의 **방문 통계 ↗** 버튼. 해당 Vercel 프로젝트 접근 권한이 있는 계정으로 로그인합니다.
- 기간과 도메인을 선택해 `www.kactstar.com` 및 `kactstar.com`의 운영 통계를 확인합니다.
- 방문자 수는 하루 단위의 익명 식별값을 기준으로 합니다. 여러 기기·브라우저·날짜에 걸친 동일인을 하나로 식별하지 않으므로 정확한 사람 수와 다를 수 있습니다.
- 페이지 조회 수에는 같은 방문자의 반복 조회가 포함됩니다. 자동화 트래픽은 Vercel이 사용자 에이전트 기준으로 필터링합니다. 광고 차단 등으로 일부 방문은 누락될 수 있습니다.
- 연결 이전의 방문 기록은 생성하지 않습니다. 배포 검수를 위해 발생한 소수의 조회는 초기 통계에 포함될 수 있습니다.

## 수집 범위

`src/analytics/policy.cjs`는 실제 두 도메인의 HTTPS 공개 화면만 허용합니다. 관리자·API·계정·비공개 자료·로컬·Vercel 미리보기·프레임 내부·`admin` 또는 `preview` 쿼리 화면은 제외합니다. 관리자 계정이 일반 공개 주소로 방문하면 일반 방문으로 집계될 수 있습니다.

현재 페이지 주소의 쿼리와 해시는 전송 전에 제거합니다. 따라서 광고 UTM 쿼리별 캠페인 분석은 수집하지 않으며 유입 경로는 Vercel이 제공하는 리퍼러 정보를 기준으로 확인합니다. 신청 내용·이름·연락처를 별도 이벤트나 회원정보로 전달하지 않습니다. Vercel 방문·체류 통계 자체는 별도 쿠키나 저장소 식별자를 만들지 않습니다. 신청 유입 연결에 사용하는 일시적인 플랫폼명 세션 저장소는 아래 신청별 출처 항목을 따릅니다.

`npm run build`가 공식 `@vercel/analytics`를 `visitor-analytics.js`로 묶고, 공개 HTML 전체에 로더를 넣습니다. 특강 신청 페이지도 포함됩니다. 공개 개인정보 처리방침 7항에 통계 안내를 반영했습니다.

## 운영 설정과 검수

Vercel 프로젝트에서 Web Analytics를 활성화한 뒤 재배포해야 `/_vercel/insights/script.js`와 수집 경로가 제공됩니다. Plus 추가 기능은 활성화하지 않습니다. 현재 Pro 요금제는 수집 이벤트 1,000건당 $0.03이며 보고서 조회 기간은 12개월입니다. 요금 변경 시 [Vercel 공식 안내](https://vercel.com/docs/analytics/limits-and-pricing)를 확인합니다.

`node --test tests/visitor-analytics.test.cjs`로 공개 화면 허용, 비공개 화면 차단, 주소 정리, 특강 포함 빌드 연결 및 브라우저 로더를 검수합니다. 운영 배포 후 공개 브라우저에서 스크립트 요청과 `/_vercel/insights/view` 수집 요청이 성공하는지 확인합니다. 방문 숫자는 집계 지연 후 통계 화면에 나타날 수 있습니다.


## 관리자 화면 내 방문 현황

관리자 편집 화면 상단과 별도 관리자 페이지에 **오늘 방문자 / 누적 방문자**를 표시합니다. 인증된 관리자에게만 `/api/admin-visitor-stats`가 응답하며, 브라우저에는 집계 숫자·기준 시각만 전달합니다. 별도 Vercel 로그인은 필요하지 않습니다.

- 오늘 방문자: 한국 시간 자정부터 현재까지 운영 환경 한 그룹으로 중복 제거한 일일 요약. 시간별 방문자를 더하지 않습니다.
- 누적 방문자: 통계 연결일인 2026년 10월 29일부터의 운영 통계를 Vercel의 누적 집계 API로 조회합니다. 날짜·브라우저·기기가 다르면 같은 사람도 별도 방문자로 포함될 수 있습니다.
- 화면은 1분마다 갱신하며 서버에서도 최대 1분 동안 같은 집계를 재사용합니다. 한국 날짜가 바뀌면 기존 캐시를 재사용하지 않습니다. Vercel 자체 집계 지연은 별도입니다.
- 조회 실패 시 임의의 0명을 표시하지 않습니다. 이전 정상 수치가 있으면 갱신 지연임을 표시합니다.
- 필요한 서버 설정은 `VERCEL_ANALYTICS_TOKEN`입니다. 전용 프로젝트 범위 토큰을 Production의 Sensitive 환경변수로 저장해야 합니다. 클라이언트 접두사 `VITE_`를 사용하거나 값을 소스에 쓰지 않습니다. 연결키는 이 프로젝트로 범위를 제한했고 2027년 10월 29일에 만료됩니다. 만료 전에 같은 프로젝트 범위로 교체해야 합니다.
- 로컬 `--demo`에서는 **미리보기 예시** 표시와 함께 12명 / 37명을 보여줍니다. 실제 방문 기록이 아닙니다.

## 관리자 유입 경로

방문 현황 옆 **유입 경로** 링크로 `/admin/visitor-sources` 전용 관리자 페이지에 이동한 뒤 오늘·최근 7일·최근 30일을 선택합니다. 페이지 주소의 `period=7d` 또는 `period=30d`로 선택 기간을 유지할 수 있습니다. 직접 접속한 경우에도 기존 관리자 인증을 확인하고 필요 시 로그인 화면을 표시합니다. 한국 시간 자정부터 계산하며, 출처 도메인별 방문자와 조회 수를 표시합니다. 네이버·구글·인스타그램·페이스북·다음·카카오·유튜브는 이름과 실제 도메인을 함께 표시하고, 다른 출처는 도메인을 그대로 표시합니다.

`/api/admin-visitor-sources`는 기존 관리자 인증과 서버의 프로젝트 전용 연결키를 사용합니다. 고정된 운영 프로젝트의 `referrerHostname`만 조회하며 링크의 경로나 검색어, 신청 내용은 전달하지 않습니다. 상위 20개 출처 및 Vercel이 반환하는 기타 묶음을 표시합니다. 페이지가 보이는 동안 1분마다 갱신합니다.

**직접 방문·확인 불가**에는 직접 주소 입력·즐겨찾기뿐 아니라 출처를 전달하지 않는 일부 앱과 메신저 유입이 포함됩니다. 출처가 없다는 이유만으로 특정 광고나 플랫폼 유입이라고 추정하지 않습니다. 한 방문자가 여러 출처를 이용하면 경로별 방문자 합계가 전체 방문자보다 클 수 있으므로 비율을 임의로 계산하지 않습니다. 현재 주소의 UTM 쿼리는 수집 전에 제거하므로 캠페인 이름별 분석은 이 화면에 포함하지 않습니다.

추가 검수: `node --test tests/admin-visitor-sources.test.cjs tests/admin-visitor-summary.test.cjs`.


## 플랫폼 통합과 구간별 체류

주요 플랫폼의 기본 도메인과 하위 도메인을 하나로 묶습니다. 플랫폼별로 Vercel에 범위 필터를 적용한 단일 집계를 요청해, 같은 방문자가 `m.facebook.com`과 `l.facebook.com`을 모두 이용해도 페이스북에서는 중복 제거합니다. 나머지 출처 조회에서는 알려진 플랫폼을 제외하므로 상위 목록 밖의 플랫폼 주소가 기타 경로에 다시 포함되지 않습니다.

같은 관리자 페이지의 **구간별 체류 시간**은 메인 홈페이지의 17개 본문 구간·첫 안내 팝업·수강 상담 신청 페이지·무료 특강 신청 페이지을 비교합니다. 선택 기간은 유입 경로와 함께 바뀝니다. 수강 상담 신청 페이지 /apply와 무료 특강 신청 페이지 /events/kim-jung-tae-20261107은 각각 전체 화면을 하나의 구간으로 측정합니다. 나머지 개별 상세 페이지는 체류 측정 범위에 포함하지 않습니다.

클라이언트는 화면에서 가장 크게 보이는 의미 있는 구간 한 곳을 초 단위로 관찰합니다. 탭이 숨겨지면 중단하며, 첫 안내 팝업은 별도 `event_popup` 구간으로 집계하며 팝업 뒤 본문은 제외합니다. 팝업은 추적 시작 후 생성되므로 매 관찰 시점에 확인합니다. 다른 팝업은 계속 제외합니다. 조작 없이 60초가 지나면 일시 중단하되 재생 중인 소개 영상은 계속 측정합니다. 타이머가 오래 정지한 시간은 보수적으로 제외합니다. 키 입력의 내용·마우스 위치·회원 식별정보·화면 녹화·별도 쿠키나 저장소 식별자는 수집하지 않습니다.

공식 Vercel `track()`으로 `section_seen`, `section_time_10s`, `section_time_5s`, `section_time_1s` 이벤트와 고정 구간 ID만 전송합니다. 기본 전송은 10초 간격이고 구간 이탈·탭 전환·종료 시 나머지 정수 초를 5초·1초 단위로 보냅니다. 1초 미만의 나머지는 전달되지 않을 수 있습니다. Pro의 기존 이벤트 단가가 적용되며, 체류 중 방문자당 기본 약 6건/분에 구간 전환 시 잔여 이벤트가 추가됩니다.

관리자 서버는 4개 이벤트 × 21개 구간(최대 84그룹)을 한 번의 집계 조회로 읽습니다. 누적 시간은 이벤트별 초 값을 가중 합산하고, 방문자당 평균은 누적 시간을 `section_seen`의 익명 방문자 수로 나눕니다. 광고 차단·종료 시 전송 누락·익명 방문자 식별의 한계가 있어 실제 시선이나 독서 시간을 의미하지 않습니다. 연결 이전의 체류 기록은 복원하지 않습니다. 초기 검수 방문이 통계에 포함될 수 있습니다.

검수: `node --test tests/engagement.test.cjs tests/admin-visitor-sources.test.cjs tests/visitor-analytics.test.cjs`.

## 신청별 최초 출처와 측정 범위 비교 (2026-10-29 추가)

신청별 출처는 attribution_source의 고정 플랫폼 코드로 보관합니다. 방문 탭의 세션 저장소에는 플랫폼 코드·만료 시각만 저장하며 내부 이동 시 최초 출처를 유지합니다. 마지막 페이지 이동 후 30분 만료입니다. 알려진 유입 플랫폼 표시나 외부 referrer의 호스트만 분류하고 원문 URL·검색어·개인정보·방문자 ID는 저장하지 않습니다. 출처가 없는 첫 방문은 direct, 내부 이동인데 이전 기록이 없거나 잘못된 데이터면 unknown, 알려지지 않은 외부 출처는 other입니다. 신청 API는 허용 코드만 저장합니다. 브라우저가 전달하는 유입 정보이므로 광고 실적을 보증하거나 위변조를 방지하는 결제 지표가 아닙니다.

승인받은 Supabase 관리 화면에서 supabase/migrations/20261029_application_attribution.sql을 적용했습니다. 기존 신청은 null(출처 미수집)로 유지합니다. 과거 메모의 인스타그램 표시나 현재 방문 플랫폼 비율을 사용해 기존 출처를 채우지 않습니다. 관리자 전용 /api/admin-application-sources는 service_role 전용 집계 함수를 호출해 플랫폼별 수강 상담·11/7 무료 특강 접수 합계만 반환하며 신청자의 이름·전화·메모를 읽지 않습니다. 신청 종류·기간은 기존 카드와 동일하며 수정·중복 특강 재접수로 새 건수를 만들지 않습니다.

체류 기록은 공개 상세 페이지까지 확장하고 기타 공개 페이지로 묶습니다. 관리자·미리보기·계정 제외는 유지합니다. 전체 방문 대비 체류 기록 인원은 동일 기간에 환경 한 그룹으로 집계한 방문자 수와 section_seen 방문자 수를 비교합니다. 구간별 방문자를 더하지 않습니다. 전체 방문이 더 크면 차이를 표시하되 원인별 분배나 가상 체류 기록을 만들지 않습니다. 역전되면 집계 시차로 안내하며 임의로 0명에 맞추지 않습니다.

## 시간당 조회와 제한 시 보존 (2026-10-29 후속 수정)

사용자 요청에 따라 관리자 방문 요약·유입 경로·체류·신청 출처 조회를 시간당 한 번으로 조정했습니다. 방문/체류 수집 타이머는 바꾸지 않았고 관리자 보고서 폴링 및 서버 캐시만 한 시간입니다. 관리자 인증은 캐시 응답에서도 확인하며 한국 날짜가 바뀌면 전날 스냅샷을 사용하지 않습니다.
