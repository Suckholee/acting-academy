# AXYZ 방식의 회원 인증 및 계정 관리

참고 자료는 aiedu1 프로젝트의 `output/pdf/AXYZ-001-online.pdf` 20~24페이지와 AXYZ-LOGIN-001입니다. 로그인 시작뿐 아니라 가입·복구·계정 연결·세션·권한 검수를 포함합니다.

## 화면

- `/login`: 카카오·Google로 계속하기, 이메일 로그인, 복구 도움말
- `/signup`: 이름·이메일·비밀번호·동의, 이메일 코드 인증, 재발송·주소 수정
- `/reset-password`: 가입 여부를 노출하지 않는 복구 안내
- `/account`: 본인 정보, 로그인 수단 연결·해제, 비밀번호 변경, 로그아웃, 탈퇴 요청
- `/admin/members`: 별도 관리자 인증, 회원 검색, 페이지 이동, 이용 가능·중지·탈퇴 요청 관리

현재 미리보기는 `--demo`로만 동작하는 로컬 인증 모형입니다. 이메일 가입 후 인증 코드 `123456`을 입력하면 됩니다. 소셜 버튼은 외부 제공자 인증을 하지 않는 시뮬레이션입니다. 데이터는 메모리에만 저장되고 서버 재시작 시 초기화됩니다. 데모 비밀번호는 실제 사용자 비밀번호를 사용하지 마세요.

## 하나의 회원 여러 로그인 수단

기준 회원은 Supabase `auth.users.id`이며 `academy_members.user_id`와 1:1로 연결됩니다. Google·카카오 등 제공자 식별자는 Supabase Auth의 identity로 관리합니다. 회원 정보나 수강 데이터를 이메일 문자열에 연결하지 않습니다.

검증된 동일 이메일의 자동 연결은 Supabase Auth의 공식 정책을 사용합니다. 이메일이 다른 경우 기존 계정에 로그인한 상태에서 `linkIdentity`를 실행하고 외부 제공자의 인증을 완료합니다. 앱에서 이름·전화번호·이메일 유사성을 근거로 자체 병합하지 않습니다. 이미 다른 회원에 연결된 로그인 수단은 오류로 안내하며, 두 계정 소유권 확인과 데이터 충돌 정책 없이 자동 통합하지 않습니다. 별도 회원 둘을 병합하는 기능은 구현하지 않았습니다.

소셜 가입 회원도 내 계정의 이메일 로그인 추가에서 비밀번호를 설정하면 같은 ID의 이메일 로그인 수단을 추가할 수 있습니다. 연결을 해제해도 마지막 로그인 수단은 유지합니다. 연결 해제, 서비스 로그아웃, 외부 제공자의 권한 철회, 탈퇴 요청은 다른 동작입니다. 탈퇴 요청은 즉시 영구 삭제가 아닌 상태 변경이며 운영자의 처리·보관 정책 확정이 필요합니다.

## 운영 연결

1. 기존 CMS 마이그레이션과 보안 마이그레이션 뒤 `20261012_members.sql`을 적용합니다.
2. 서버 환경에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다. 회원관리에는 기존 `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`도 필요합니다. service-role 키는 브라우저에 공개하지 않습니다.
3. Supabase Auth에서 이메일 확인을 켜고, Google·Kakao 제공자 키와 동의 항목을 설정합니다. 제공자 계정에 인증된 이메일이 없으면 다른 로그인 수단을 안내합니다.
4. Supabase에서 Manual identity linking을 활성화합니다. 설정을 마친 제공자를 `MEMBER_OAUTH_PROVIDERS=google,kakao`로 지정합니다. 아직 설정되지 않은 제공자는 준비 중 안내로 처리합니다.
5. Redirect URLs에 실제 사이트의 `/account`, `/account?recovery=1`을 등록합니다. PKCE 인증 코드는 공식 SDK가 교환합니다. Google 로그인을 위해 Gmail 접근 권한을 요청하지 않습니다.
6. 가입 인증 메일 템플릿에는 `{{ .Token }}` 인증 코드를 표시합니다. 비밀번호 복구 메일은 공식 확인 링크를 사용하고 복귀 주소가 `/account?recovery=1`인지 확인합니다. 운영 SMTP·발송 및 시도 제한을 설정합니다.
7. 승인된 이용약관·개인정보 처리방침을 사이트에 게시하고 해당 내부 경로를 `MEMBER_TERMS_URL`, `MEMBER_PRIVACY_URL`에 지정합니다. 이 설정 전에는 실제 이메일 가입 및 소셜 가입 마무리를 제한합니다.

## 보호 및 검증 상태

회원 API는 SDK 세션을 신뢰하는 데 그치지 않고 서버에서 `auth.getUser(token)`으로 인증 결과를 검증합니다. 요청 본문의 사용자 ID는 무시하고 검증된 ID로만 프로필을 조회·수정합니다. 회원 테이블은 브라우저 직접 접근을 막고 관리자 API도 별도 관리자 인증을 검사합니다.

세션 만료 시 내 정보 입력 초안은 이 탭의 sessionStorage에 회원 ID별로 보관하고 다시 로그인한 같은 회원에게만 복구합니다. 비밀번호·코드·토큰은 초안에 저장하지 않으며 명시적 로그아웃 시 초안을 삭제합니다. 서비스 인증 토큰의 보관·갱신·로그아웃은 Supabase 공식 SDK가 수행합니다.

자동 테스트는 로컬 코드·인증 경계·회원 격리·RLS·재사용 코드 거부·계정 연결의 같은 회원 ID 유지·다른 회원 충돌 거부를 검증합니다. 실제 Google·카카오 OAuth, 운영 이메일 전달과 코드 만료, 운영 세션 만료 및 비밀번호 복구 링크 재사용 거부는 제공자·Supabase 연결 후 별도로 검증해야 합니다. 실제 계정 연결 및 저장이 완료된 것으로 표시하지 않습니다.

공식 참고: https://supabase.com/docs/guides/auth/auth-identity-linking 및 https://supabase.com/docs/guides/auth/passwords

## 2026-10-26 정책 공개와 가입 개시 분리

이용약관 `/terms`, 개인정보 처리방침 `/privacy`는 공개되어도 신규 회원가입은 자동으로 열리지 않습니다. `MEMBER_REGISTRATION_OPEN=true`를 별도로 설정하고 운영 기준 확인 및 검수를 마쳐야 개시합니다. 기본값은 보류입니다. `/api/member-config`의 `policiesReady`와 `registrationOpen`은 서로 다른 상태입니다. 가입 보류 화면에서는 개인정보 입력 양식을 표시하지 않습니다.

## 2026-10-26 세 가지 가입·로그인 방식 사전 구현

- 카카오: Supabase Kakao OAuth와 기존 계정의 인증된 로그인 수단 연결을 사용합니다. 카카오 개발자 앱의 REST API 키·Client Secret, Kakao Login 활성화, 동의 항목, Supabase callback 주소와 `/account` 복귀 허용 주소 설정이 필요합니다. 연결 전에는 버튼이 비활성화됩니다. 가입자가 계정 연결을 직접 인증해야 하며 이름·전화번호만으로 합치지 않습니다.
- 이메일: 이름·이메일·휴대전화·비밀번호·동의를 받고 인증 메일을 발송합니다. 이메일 소유 확인 후 이용합니다. 문자는 발송하지 않으며 휴대전화 명의 인증으로 표시하지 않습니다.
- 별도 아이디: 위 정보에 영문으로 시작하는 4~20자 영문·숫자·밑줄 아이디를 추가합니다. 아이디는 대소문자를 구분하지 않으며 관리자용 예약어와 중복을 거부합니다. 이메일 인증 후 아이디를 확정하고, 인증 도중 중복된 경우 내 계정에서 다른 아이디를 선택합니다. 비밀번호는 별도로 저장하지 않고 기존 Supabase 계정의 비밀번호를 사용합니다.
- 아이디 로그인은 서버에서 회원을 찾아 인증합니다. 비로그인 응답에 연결 이메일을 공개하지 않으며 IP별·전체 시도 제한을 적용합니다. 아이디·이메일 로그인은 같은 회원 ID를 유지합니다.
- `20261026_member_usernames.sql`은 아이디별·회원별 유일성, 브라우저 직접 읽기·쓰기 차단 및 서버 전용 시도 제한을 제공합니다. 운영 저장소에 적용한 뒤 코드를 배포합니다.
- `/api/member-auth`의 가입 요청도 `MEMBER_REGISTRATION_OPEN`을 확인합니다. 공개 가입을 열 때만 명시적으로 `true`로 바꿉니다. 정책 페이지를 공개하는 것만으로 가입이 열리지 않습니다.
- 운영 공개 전 카카오 자격정보 연결, 실제 이메일 전달·인증 코드 만료, 정책·전화 필수 수집 안내와 연령 기준을 확인해야 합니다. 로컬 데모의 123456은 운영 인증 코드가 아닙니다.

공식 Kakao 연결 안내: https://supabase.com/docs/guides/auth/social-sign-in/auth-kakao

## 운영 가입 보류 확인 (2026-10-26)

운영 Supabase의 Authentication → Sign In / Providers → Allow new users to sign up도 꺼 두었습니다. 실제 API 설정의 `disable_signup=true`, 이메일 확인 활성화 및 홈페이지 가입 API의 403 응답을 확인했습니다. 운영자 답변 이후 개시할 때만 Supabase 신규 가입 허용과 `MEMBER_REGISTRATION_OPEN=true`를 함께 적용하고 실제 이메일 발송 및 카카오 연결 검수를 수행합니다.

## 표준 회원 운영 기준 반영 (2026-10-26)

사용자 승인에 따라 회원정보는 회원 탈퇴 시까지 보유·이용하고, 탈퇴 접수 후 본인 확인 및 법령상 보존 대상 확인 뒤 지체 없이 파기하는 기준으로 정리했습니다. 필수 항목은 이름·이메일·휴대전화·비밀번호 인증정보 및 계정·인증·동의 기록이고 아이디 가입 시 아이디가 추가됩니다. 약관 동의와 개인정보 수집·이용 동의를 분리했습니다. 개인정보 보호업무·고충처리 창구는 기존 아카데미 운영팀 및 대표번호 02-2666-4528로 안내하며 특정인의 책임자 지정을 임의로 기재하지 않습니다.

보관기간·동의 항목에 대한 운영자 답변 대기는 종료합니다. 카카오 자격정보, 실제 이메일 인증, 국외 처리 구성 고지는 실제 설정 확인 사항이므로 표준 문구로 대체하지 않습니다. 가입 개시 설정은 이 변경만으로 활성화하지 않습니다. 탈퇴 요청은 여전히 운영자의 후속 파기가 필요한 수동 절차입니다.
