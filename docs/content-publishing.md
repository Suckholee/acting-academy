# 정보성 콘텐츠 발행

관리 주소: `/admin/editorial` · 공개 목록: `/journal`

본문의 사진과 그림에는 카드 제목이나 중복 요약을 캡션으로 붙이지 않습니다. 그림은 관련 본문과 함께 읽고, 화면을 보지 못하는 독자를 위한 이미지 대체 설명은 유지합니다. 별도 카드뉴스와 PNG 저장에서는 제목 앞의 `웹툰 ·` 같은 형식 표시를 빼고 주제만 표시합니다.

연기 노트 목록·본문·오류 화면과 관리자 발행 미리보기에는 홈페이지와 같은 전체 메뉴를 표시합니다. 화면 폭이 좁으면 `메뉴`를 눌러 아카데미 소개부터 공지사항까지 이동합니다. 모바일 메뉴는 브라우저 기본 펼침 기능을 사용하므로 스크립트를 실행하지 않는 관리자 미리보기에서도 열립니다.

글의 첫 사진과 상황별 설명에 해당하는 사진을 본문 사이에 표시합니다. 제목·이미지 설명·장면 설명에 `웹툰` 또는 `webtoon`이 있는 그림은 두 번째 상황별 설명 다음에 원래 비율로 표시해 전체 장면이 잘리지 않게 합니다. 이 배치는 관리자 발행 미리보기와 공개 글이 함께 사용합니다. 기존 초안의 내용이나 비공개 상태는 변경하지 않습니다. 관리자 HTML과 화면 파일은 캐시하지 않고, 빌드할 때 파일 내용별 버전 주소를 붙입니다.

기존 홈페이지 관리자 계정으로 로그인합니다. 홈페이지 편집 도구의 `콘텐츠 발행`에서도 이동할 수 있습니다.

저장한 글은 실제 게시 페이지와 같은 발행 화면으로 먼저 열립니다. `PC`와 `휴대폰`으로 화면 크기를 바꾸거나 `크게 보기`로 확인할 수 있습니다. `내용 편집`에서 수정하고 `발행 화면으로 보기`를 누르면 저장 전 내용도 반영됩니다. 미리보기만 열어서는 저장하거나 공개하지 않습니다. 아직 게시하지 않은 글의 날짜는 게시 전으로 표시합니다.

1. 키워드와 실제 강사 경험·참고 내용을 입력하고 AI 전송에 동의한 뒤 `글·카드뉴스 초안 만들기`를 누릅니다.
2. 글 제목·소개·본문·작성자, 카드 3~8장의 이미지와 문구를 수정하고 미리보기에서 확인합니다. 카드마다 서로 다른 장면의 AI 이미지를 자동으로 생성합니다. 이미지 장면 설명을 바꾸고 다시 생성하거나, 2MB 이하 JPG·PNG·WEBP 사진으로 교체할 수 있습니다. 사진 설명도 확인해주세요. 이미지가 포함된 카드별 PNG 파일을 저장할 수 있습니다.
3. `비공개 초안 저장`으로 저장합니다. 새로고침 후에도 보관되며 공개 목록과 API에서는 조회할 수 없습니다.
4. 모든 카드의 이미지·사진 설명을 준비하고 사실과 표현을 확인했다는 항목을 선택하고 `확인 후 홈페이지에 게시`를 누릅니다. 같은 화면의 최신 편집 내용을 공개본으로 저장합니다.
5. 게시한 글을 다시 수정해 초안으로 저장하면 기존 공개본은 유지됩니다. 다시 검수하고 게시해야 수정 내용이 공개됩니다. `게시 중지`는 공개본만 내리고 초안을 보관합니다.

글이 게시되면 홈페이지 하단의 연기 노트 영역과 `/journal` 목록에 표시됩니다. 상세 페이지의 본문과 카드뉴스는 서버에서 공개본만 렌더링합니다. 관련 교육과정을 선택하면 상담 신청에 해당 과정이 연결됩니다. SNS 자동 발송·예약 발행은 이 기능에 포함되지 않습니다.

서버는 기존 `OPENAI_API_KEY`, `OPENAI_MODEL`, 관리자 인증과 AI 이용 제한을 사용합니다. Responses API의 구조화된 JSON 응답을 검증하며 `store:false`로 요청합니다. 실패하거나 미완료인 응답은 게시·저장하지 않습니다. AI가 연결되지 않아도 직접 작성과 저장은 가능합니다. 테스트 서버에서만 시연용 응답을 사용합니다.

데이터는 `20261101_editorial.sql`의 `academy_editorial` 테이블에 저장합니다. 초안·검수 메모는 관리자 API만 읽습니다. 공개 조회에는 공개본·게시일·글 ID만 선택합니다. 수정 시 저장 버전 조건을 적용해 다른 창의 내용을 조용히 덮어쓰지 않습니다. 공개 HTML은 모든 입력을 이스케이프합니다. 게시된 콘텐츠는 개인정보·성과·제휴·일정 등을 확인한 뒤 운영자가 책임지고 게시합니다.

이미지 생성은 관리자 전용 `/api/admin-editorial-image`에서 Images API(`OPENAI_IMAGE_MODEL`, 기본 `gpt-image-2`)를 호출합니다. 키와 생성 결과의 바이트는 서버에서만 처리하며 검증한 JPEG를 기존 미디어 저장소에 보관합니다. 카드별로 호출하므로 일부 실패해도 완성된 글과 이미지는 화면에 유지됩니다. `빠진 이미지 모두 생성`으로 이어서 준비할 수 있습니다. AI 이미지는 가상 장면임을 편집 화면에서 안내합니다. 게시 시 모든 카드에 이미지와 대체 설명이 있어야 하며, PNG 저장 중 사진 로딩에 실패하면 텍스트만 있는 파일을 만들지 않고 오류를 안내합니다.

## 오디션 준비생의 질문 중심 콘텐츠

질문·키워드 한 개에서 출발합니다. 예: “연기 경험이 없는데 첫 오디션은 어떻게 준비하나요?”, “직장인이 퇴근 후 무엇부터 준비해야 하나요?”, “셀프테이프에서 카메라를 봐야 하나요?” 관리 화면의 질문 예시는 주제 아이디어이며 실제 검색량을 집계한 결과는 아닙니다.

생성 초안은 대표 질문과 직접 답하는 핵심 답변, 도입·독자 상황, 상황별 질문과 구체적인 답변, 이어서 궁금할 질문으로 나눕니다. 연습 순서·선택 기준·실수·조건과 예외를 설명하며 카드 5장도 같은 답변을 요약합니다. 마지막 카드를 자동으로 학원 상담 광고로 만들지 않습니다. 상담 링크는 글을 읽은 다음 별도 영역에서 제공합니다.

학원의 실제 지도 기준이나 경험은 `강사 경험·참고 내용`에 넣습니다. 확인한 공개 자료는 `자료명 | https://주소`를 한 줄에 하나씩 입력합니다. URL을 적는 것만으로 원문을 자동 조회하거나 검증하지 않습니다. 사용할 원문 발췌도 참고 내용에 넣고 원문을 직접 대조해야 합니다. AI가 출처 URL을 새로 만들어 넣지 못하게 공개 출처 목록은 입력한 자료만 보관합니다. 일반 팁과 개별 오디션 공고의 지원 자격·제출 규격을 구분합니다.

게시할 때 대표 질문·핵심 답변, 상황별 질문 2개와 관련 질문 2개 이상, 카드별 이미지·사진 설명을 갖추고 검수를 선택해야 합니다. 기존 초안은 그대로 열고 저장할 수 있으며 질문 구조를 채워 다시 게시합니다. 기존 공개 글은 이전 형식도 계속 표시합니다.

공개 페이지는 첫 화면의 핵심 답변, 목차, 질문형 소제목, 펼쳐진 관련 질문, 실제 입력한 출처, 작성 주체·게시일·최근 수정일을 서버 HTML에 담습니다. Article·BreadcrumbList·FAQPage JSON-LD는 같은 공개본만 설명하며 사용자 입력의 스크립트 문자를 안전하게 처리합니다. 최근 수정일은 비공개 수정 시 바뀌지 않고 재게시할 때 갱신됩니다. `/journal-sitemap.xml`은 공개된 글만 싣고 robots.txt에서 안내합니다.

이 구성은 읽기 쉽고 근거를 확인할 수 있는 글을 만드는 방법입니다. AI 인용·추천·순위·검색 노출을 보장하지 않습니다. Google은 AI 검색에 별도의 특수 마크업이 필요하지 않으며 보이는 본문과 구조화된 데이터의 일치, 텍스트 접근성, 내부 링크와 유용한 고유 내용을 강조합니다. FAQPage는 질문과 답변을 표현하는 Schema.org 어휘이며 Google의 FAQ 리치 결과 노출을 의미하지 않습니다.
