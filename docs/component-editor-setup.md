# 컴포넌트 직접 편집 운영 안내

실제 배포 디자인의 소스는 `published-source/`, 편집 소스는 `src/published-editor/`에 있습니다. `npm run build`는 `dist-published/`를 만들고 Vercel도 이 폴더를 사용합니다. 기존 React 개발 화면과 `dist/`의 작업은 덮어쓰지 않습니다. `build:legacy`는 이전 생성 스크립트 보관용이며 현재 삭제된 정적 파일을 복원하지 않습니다.

## 편집

일반 방문자에게는 관리자 모드 버튼이 표시되지 않습니다. 편집할 페이지 주소 뒤에 `?admin=1`을 붙이면 버튼이 나타납니다(기존 쿼리가 있으면 `&admin=1`). 예: `https://www.kactstar.com/?admin=1`. 이 주소는 로그인 버튼만 표시하며 관리자 인증은 그대로 필요합니다.

관리자 모드 → 로그인 → 홈페이지 컴포넌트 클릭 → 해당 문구·사진 편집 → 컴포넌트에 적용 → 홈페이지에 저장. 저장 전 변경은 현재 페이지에서만 보입니다. 취소하면 마지막 저장 상태로 돌아갑니다. 방문자 미리보기에서는 링크와 사진 갤러리를 원래처럼 사용할 수 있습니다.

대상은 메인, 교육과정 카드, 강사 카드 및 상세 프로필 영역, 시설, 수강료, FAQ, 과정 상세 페이지의 커리큘럼입니다. 수강료와 과정 카드의 공통 필드, 강사 이름·직함은 공통 데이터로 관리합니다. 강사 사진과 경력은 페이지별로 관리합니다. 교육과정 카드의 편집창에 커리큘럼 항목도 표시되며, 저장 후 과정 상세 페이지와 방문자 커리큘럼 팝업에 함께 반영됩니다.

저장소 미연결 시 저장 버튼은 비활성화됩니다. 실제 서버 저장과 사진 업로드, 다른 기기의 방문자 화면 반영은 운영 연결 후 확인해야 합니다. 이 작업에서는 외부 배포나 운영 데이터 변경을 실행하지 않았습니다.

## 2026-10-14 보안 보완 적용

운영 코드 배포 전에 기존 CMS 보안 마이그레이션과 `20261014_admin_sessions.sql`을 Supabase SQL 편집기에서 순서대로 적용하세요. 새 테이블과 함수가 없거나 저장소에 연결하지 못하면 관리자 로그인·조회·수정을 거부합니다. 운영 인증에 메모리 저장소로 우회하는 경로는 없습니다.

관리자 로그인은 IP별 15분 동안 5회, 전체 15분 동안 100회로 제한합니다. 성공한 로그인도 시도 횟수에 포함합니다. 제한 시 HTTP 429와 `Retry-After`를 반환합니다. Vercel에서는 플랫폼이 설정하는 `x-vercel-forwarded-for`를 사용하며 일반 프록시의 사용자 입력 헤더를 신뢰하지 않습니다. 다른 호스팅 환경에서는 직접 연결의 IP를 사용하므로 프록시를 추가한다면 신뢰 경계를 별도로 설정해야 합니다. IP는 HMAC 값으로 저장합니다.

세션 토큰 원문은 저장하지 않습니다. 관리자 API는 매번 서버 저장소에서 세션 유효성을 확인하며 로그아웃 시 해당 세션을 삭제합니다. 이전 형식 세션은 무효화되므로 다시 로그인해야 합니다. 관리자 비밀번호나 서명 비밀키를 변경하면 기존 세션도 무효화됩니다. 만료된 세션·제한 기록은 다음 로그인 요청에서 정리됩니다. `--demo`의 메모리 인증은 루프백 전용 미리보기 서버에서만 명시적으로 주입합니다.

이전 Firebase 연동을 쓰는 프로젝트가 있다면 수정된 `firestore.rules`를 해당 Firebase 프로젝트에도 적용하세요. CMS 읽기만 공개하며 CMS 쓰기와 상담 정보의 모든 브라우저 접근을 차단합니다. 이전 React 화면의 기본 비밀번호와 localStorage 관리자 인증·상담 정보 저장은 제거했습니다. Vite 개발 서버는 `127.0.0.1`에서만 엽니다.

이 변경은 로컬 코드와 운영 적용용 SQL·규칙을 준비한 것입니다. 실제 Supabase/Firebase 적용과 Vercel 배포 후 로그인 차단, 로그아웃 뒤 쿠키 재사용 거부, 일반 방문자의 상담 조회 거부를 운영 환경에서도 확인해야 합니다.

## 저장 이력과 시점 복원

상단 `저장 이력 · 복원`에서 저장 시각·버전 번호·복원 여부를 확인합니다. `변경 내용 확인`을 눌러 현재 저장본과 선택한 이력의 차이를 본 뒤 `이 시점으로 복원`을 누릅니다. 복원 범위는 현재 페이지 하나가 아닌 **홈페이지 전체의 CMS 문구·사진 경로 및 공통 정보**입니다. 복원은 즉시 저장되어 방문자에게 반영되며, 새 버전으로 기록됩니다. 복원 전 버전을 다시 선택하면 복원도 되돌릴 수 있습니다. 이후 이력을 삭제하거나 기존 이력을 덮어쓰지 않습니다.

운영 DB에는 기존 CMS 마이그레이션 이후 `supabase/migrations/20261019_content_history.sql`을 적용해야 합니다. 새 저장 API는 이력 전용 저장 함수를 호출하므로 마이그레이션이 없으면 저장을 실패 처리합니다. CMS 저장과 이력 기록은 같은 DB 트랜잭션으로 처리하며, 중간 실패 시 둘 다 롤백됩니다. 저장·복원 시 현재 버전이 맞는지 검사하므로 다른 관리자가 먼저 저장한 내용을 조용히 덮어쓰지 않습니다. 이력 조회와 복원은 관리자 인증이 필요하며, 이력 테이블은 서버의 조회·추가 권한만 허용합니다.

이력 수집을 시작하는 시점의 저장본도 보관합니다. 수집 시작 전의 과거 내용, 아직 저장하지 않은 타이핑 단계, 이미지 파일 자체, 배포된 코드·레이아웃, 회원·상담 데이터는 복원하지 않습니다. 업로드된 사진 파일은 예전 경로를 유지해야 과거 사진도 표시됩니다. 이력은 50개씩 추가로 불러올 수 있으며 자동 삭제는 하지 않습니다. 운영자 개인별 계정·작업자 식별은 기존 공통 관리자 인증과 별도로 구현해야 합니다.

로컬 시연의 이력은 서버 메모리에 있으므로 서버 재시작 시 초기화됩니다. 필요하면 `--demo --seed=/절대경로/공개콘텐츠스냅샷.json`으로 기존 공개 CMS 내용과 버전을 이력 수집 시작 시점으로 가져올 수 있습니다. 운영 이력은 DB에 저장되므로 서버 재시작과 무관하게 보관됩니다.


## 영상 영역 등록 (2026-10-19)

`배우의 길을 함께 걷는 사람들`과 홍보 영상 카드 등 `.video-slot-frame`이 있는 영역의 편집 패널 맨 위에 `영상 등록`이 표시됩니다. MP4·WEBM 파일(최대 100MB)을 선택하거나 YouTube·Vimeo·직접 재생 가능한 HTTPS MP4/WEBM 링크를 입력합니다. 패널 미리보기 → 영역에 적용 → 홈페이지에 저장 순서로 진행합니다. 기존 사진 항목은 영상 표지로 사용합니다. 영상 비우기 후 저장하면 원래 준비 안내 화면으로 돌아갑니다.

영상 플레이어는 기본 재생 컨트롤을 제공하고 자동 재생하지 않습니다. MP4·WEBM은 파일 플레이어, YouTube·Vimeo는 허용된 공식 플레이어 주소로 변환해 표시합니다. 임의 HTML·iframe 코드는 입력받지 않습니다. 대표 강사진 소개 영상은 메인·소개 페이지의 같은 영상 영역에서 공통으로 사용합니다. 홍보 영상 카드는 각각 별도로 등록합니다.

운영 환경에서는 `supabase/migrations/20261019_video_storage.sql`을 적용하세요. 기존 서버 전용 Supabase 설정을 사용합니다. 인증된 관리자 API가 임의의 새 파일 경로에 업로드할 서명 URL을 발급하고, 브라우저가 100MB 제한 영상 버킷으로 직접 업로드합니다. 서버리스 요청 본문 크기 제한을 피하며 서비스 키는 브라우저에 노출하지 않습니다. 기존 사진 버킷과 영상 버킷을 구분합니다.

로컬 `--demo`에서는 실제 파일을 메모리에 업로드하고 byte-range 재생을 지원합니다. 영상당 100MB, 전체 300MB까지 시연하며 재시작 시 시연 파일은 사라집니다. 운영 스토리지는 파일을 보관합니다. 업로드만으로 홈페이지에 게시되지는 않으며, 적용·저장을 완료해야 합니다.

영상 주소와 표지 변경은 기존 저장 이력에 포함되며 이전 시점으로 복원할 수 있습니다. 파일 자체를 이력에 복제하지 않으므로 과거 사진·영상 파일을 삭제하면 해당 파일을 재생할 수 없습니다.


## 전체 페이지 공통 관리자 적용

주요 페이지 9개(메인·소개·교육과정·강사·작품·후기·시설·FAQ·파트너스), 과정 상세 6개, 강사 상세 4개, 작품 상세 4개까지 총 23개의 공개 페이지에서 같은 관리자 도구를 제공합니다. 왼쪽 페이지 메뉴의 상세 분류를 펼쳐 직접 이동할 수 있고, 현재 페이지의 편집 영역 목록이 자동으로 바뀝니다. 상세 페이지도 직접 타이핑·문구 AI 제안·사진 업로드·저장 이력/복원을 공통으로 사용합니다.

중첩된 강사 소개 영상·작품 영상·홍보 영상 카드에는 같은 영상 등록 도구가 표시됩니다. 강사 프로필 사진 갤러리는 현재 보이는 사진 외 나머지 등록 사진도 상세 패널에서 함께 편집할 수 있습니다. 파트너스는 기관별 로고·안내 영역으로 나눠 편집합니다. 강사/작품 카드에서는 해당 상세 페이지의 편집 화면으로 바로 이동할 수 있습니다.

목록 필터, 프로필 사진 선택, 작품활동 탭, 영상 카드 이동은 편집 중에도 작동합니다. 기존 게시물·프로필의 항목 추가·삭제나 레이아웃 변경은 포함하지 않으며, 기존 공개 콘텐츠를 수정하는 범위입니다. 일반 방문자에게는 관리자 도구가 표시되지 않습니다.

## 인라인 AI 채팅과 사진 후기

각 페이지의 영역을 선택하고 오른쪽 패널의 **AI에게 요청**을 누릅니다. 예: 사진을 첨부하고 `이 사진으로 수강후기 써줘. 소감: 대본을 함께 읽으며 긴장이 풀렸어요.`라고 요청합니다. 사진은 최대 3장, JPG·PNG·WEBP 원본 12MB까지이며 전송 전에 크기를 줄이고 메타데이터를 제거합니다. 실제 수업·소감이 없으면 AI는 추가 설명을 묻습니다. 사진만으로 수강 경험이나 성과를 만들어내지 않도록 지시합니다.

변경 전후를 확인한 뒤 **변경안 화면에 적용 → 홈페이지에 저장** 순서로 반영합니다. 사진은 적용할 때 업로드됩니다. 대화와 첨부만으로 게시되지 않습니다. 기존 저장 이력에서 이전 시점으로 복원할 수 있습니다. 대화·첨부 상태는 브라우저 메모리에서만 유지되며 새로고침하면 초기화됩니다.

23개 페이지의 편집 영역은 `content/editor-registry.json`에 등록됩니다. 빌드 시 동일한 DOM 스캐너로 생성한 모듈 ID와 텍스트·이미지·영상 항목만 서버가 허용합니다. HTML, CSS, 레이아웃 편집이나 새로운 카드 추가는 지원하지 않습니다. 기존 경로 기반 저장 키는 별칭으로 읽어 이전 저장본을 유지합니다. 개발자가 기본 구조를 바꾸면 모듈 ID와 기존 저장값 이전 여부를 확인해야 합니다.

실제 연결은 서버의 `OPENAI_API_KEY`, `OPENAI_MODEL`과 기존 AI 사용량 제한 SQL 설정을 사용합니다. 모델은 이미지 입력과 Structured Outputs를 지원해야 합니다. `/api/admin-inline-ai`는 관리자 로그인·동일 출처·허용 항목·미디어 주소·응답 구조를 검증합니다. 실제 전송에는 패널의 전송 동의가 필요합니다. OpenAI 응답은 `store:false`로 요청하며 서버는 임의 코드 실행이나 자동 저장을 하지 않습니다.

로컬 `--demo`는 규칙 기반 시연입니다. 사진 첨부·변경안·적용·저장·복원을 확인할 수 있지만 사진 해석이나 자유로운 AI 문장 생성은 하지 않습니다. 시연 사진과 이력은 서버 재시작 시 사라집니다. 실제 OpenAI 호출은 별도 설정 후 확인해야 합니다.

API 참고: [이미지 입력](https://developers.openai.com/api/docs/guides/images-vision), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## 로컬 공개 콘텐츠를 Supabase로 이관

`node --env-file=.env.local scripts/migrate-local-content.cjs`는 실제 저장본과 로컬 등록 항목을 비교하는 읽기 전용 사전 점검입니다. `--snapshot=/절대경로/콘텐츠스냅샷.json`으로 이전에 저장한 로컬 수정본을 포함할 수 있습니다. 서버에 이미 저장된 값이 우선이며, 없는 항목만 로컬 수정본과 기본 콘텐츠로 채웁니다. 시연 회원·문의는 가져오지 않습니다.

검토 후 `--apply`를 추가하면 등록된 로컬 사진·영상을 내용 해시 기반 새 스토리지 경로에 올리고, 모든 파일의 크기·접근 상태를 확인한 뒤 CMS를 하나의 새 저장 이력으로 반영합니다. 중간에 다른 관리자가 저장하면 버전 충돌로 CMS 반영을 중단합니다. 이전 저장본과 결과 파일은 `output/migration/`에 보관합니다. 이 폴더의 스냅샷은 버전 관리에 포함하지 마세요. 사이트 기본 디자인과 HTML은 기존 배포 소스를 유지합니다.

## 화면 범위에 대응하는 콘텐츠 관리

FAQ·수강후기·강사·교육과정·수강생 작품·시설·파트너스 페이지에서는 목록 바로 앞의 녹색 **목록 관리** 버튼 또는 왼쪽 콘텐츠 관리 메뉴를 누릅니다. 전체 목록은 녹색 테두리로, 개별 콘텐츠는 해당 카드 테두리로 표시하며 오른쪽 패널에 선택 범위를 설명합니다. 글자를 누르면 직접 입력하고, 사진이나 카드 빈 곳을 누르면 해당 콘텐츠 편집을 엽니다.

목록에서 새 항목 등록, 공개·비공개 전환, 순서 변경, 수정, 삭제가 가능합니다. 신규 항목은 비공개로 시작하고, 공개 항목에는 제목 또는 질문이 필요합니다. 각 항목은 개발자가 만든 기존 카드·질문 형식만 사용합니다. 강사·작품·교육과정의 상세 연결은 기존 상세 페이지 중에서 선택하며 새 상세 페이지 생성은 포함하지 않습니다. 공개·비공개는 선택한 목록에서의 표시 여부입니다.

사진 첨부와 AI 변경안도 선택한 콘텐츠 한 개에 연결됩니다. 콘텐츠에 적용한 뒤 상단의 홈페이지에 저장을 눌러 최종 반영합니다. 목록의 항목·순서·공개 여부·사진 경로는 기존 CMS의 `/collections/종류-번호` 데이터와 같은 저장 이력 트랜잭션에 포함됩니다. 삭제 후에도 저장 이력으로 복원할 수 있습니다. 공개 CMS 응답에서는 비공개 목록 항목을 제외하고, 전체 목록과 이력은 인증된 관리자만 조회합니다. JSON 입력·임의 디자인 코드·템플릿 변경은 허용하지 않습니다.
